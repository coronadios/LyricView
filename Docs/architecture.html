Architecture

The architecture is intentionally engine-first. The lyric logic lives outside the UI. The renderer consumes state rather than owning it.

Design principles

  • Data-driven lyrics
  • Deterministic renderer state
  • Renderer remains backend agnostic
  • Timing is the source of truth
  • Extensible registration instead of hardcoded logic

Why this matters

When the renderer receives a timestamp and a lyric model, it should always produce the same visual state. That makes seeking, testing, debugging, previews, and future integrations far more reliable.

Contribution-friendly structure

The project is organized in layers so contributors can pick an area without needing to understand the whole runtime at once. The model layer defines the data, the engine resolves state, motion adds feel, and renderers adapt the result to a screen or widget toolkit.

That separation is especially important for open-source work: it makes new features easier to review, reduces accidental UI coupling, and lets experimental renderers or formats evolve without forcing a rewrite of the base behavior.
