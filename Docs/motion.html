Motion

Motion is driven by the song timeline, not by CSS-only timing. The engine computes state and the renderer transforms that state into visual motion.

from lyricview.motion.primitives import interpolate, ease_in_out_cubic

value = interpolate(0, 10, 0.5, ease_in_out_cubic)
print(value)

Motion primitives

  • linear interpolation
  • ease in/out cubic helpers
  • spring-like motion
  • scroll controller with damping
  • accessibility-aware reduced motion mode

Why it matters

Movement should preserve the emotion of the song without feeling robotic or disconnected from the actual timeline. The motion system does that by blending deterministic progress states with smooth interpolation and optional accessibility-aware fallbacks.

For OSS contributors, this is a great extension point: new easing curves, better scroll behavior, and richer visual states can be added without rewriting the playback model.
